# Lotsman: список доработок

Дата анализа: 2026-10-09.

Документ основан на обзоре кода, CLI, тестов, CI и архитектурных решений. Это
предлагаемый backlog, а не изменение требований замороженной спецификации.
Изменения публичных контрактов и архитектурных решений следует оформлять через ADR.

Полная перепись проекта не требуется. Основные направления: точность исполнения,
единая проверка исходящих запросов, жизненный цикл OAuth, достоверный аудит и
удобное подключение API.

## Приоритеты

- **P1** — исправить до стабильного релиза: безопасность, точность запросов,
  достоверность подтверждений и результата исполнения.
- **P2** — следующий этап: надёжность, ограничения ресурсов, диагностика и UX.
- **P3** — развитие возможностей после стабилизации, по потребностям интеграций.

Пункты с пометкой **подтверждено** воспроизведены диагностическими сценариями.
Пометка **по коду** означает выявленное свойство реализации, для которого ещё
нужен отдельный регрессионный или нагрузочный тест.

## P1. Корректность и безопасность

_Сделано 2026-10-09; решения — в ADR-0016 и ADR-0017 (разделы «Since then») и ADR-0019._

### 1. Проверять origin каждого исходящего запроса

- [x] Сделать `CheckTarget` обязательной частью исходящего клиента или transport.
- [x] Применять проверку к запросам получения OAuth-токена.
- [x] Сохранить запрет redirects, проверку адресов при соединении и правильный
  порядок применения credentials.
- [x] Проверить все места создания исходящих клиентов и явно описать их политики.
  API-вызов и mint построены на `egress.Policy.Client` и оба вызывают `CheckTarget`.
  JWKS и introspection (URL задаёт оператор) — `inbound.identityClient`: без redirects
  и без proxy из окружения (ADR-0016, «Since then»).

**Подтверждено:** policy отказывает origin token endpoint, но mint проходит через
транспорт. `egress.Policy.Client()` самостоятельно не вызывает `CheckTarget`;
для API-запроса проверка находится в runner, для mint её нет.

**Критерий готовности:** token endpoint вне разрешённого списка получает отказ
до обращения к транспорту; разрешённый endpoint работает. Проверки проходят
как с внедрённым тестовым transport, так и с настоящим локальным TLS-сервером.

Код: [egress/policy.go](../internal/egress/policy.go),
[auth/oauth2.go](../internal/auth/oauth2.go),
[mcpserver/runner.go](../internal/mcpserver/runner.go).

### 2. Сохранять точность чисел от MCP до HTTP

- [x] Декодировать произвольные аргументы без промежуточного `float64`:
  использовать сырые MCP-аргументы и `json.Decoder.UseNumber()`.
- [x] Сохранять `json.Number` при валидации и сериализации.
- [x] Исправить чтение аргументов в `explain-call`.
- [x] Проверить точность числовых ограничений и значений в нормализованных схемах.
  `minimum`/`maximum`/`multipleOf`/`exclusive*`, `enum` и `const` публикуются литералом
  из YAML там, где `float64` его теряет (`internal/jsonnum`).

**Подтверждено:** переданное число `9007199254740993` отправляется в query как
`9007199254740992`.

**Критерий готовности:** числа около `2^53`, границ `int64` и десятичные значения
сохраняют значение либо явно отклоняются до сети. Одинаковое поведение в tools,
search и `explain-call`; проверены path, query и JSON body.

[mcpserver/search.go](../internal/mcpserver/search.go),
[requestbuild/serialize.go](../internal/requestbuild/serialize.go),

### 4. Исправить ротацию и разрешение OAuth-секретов

- [x] Читать актуальный secret reference при фактическом mint нового токена.
- [x] Сохранять ошибку разрешения секрета вместо подстановки пустой строки.
- [x] Отказывать до сети при отсутствующем, пустом или нечитаемом секрете.
- [x] Сохранить общий кэш токенов для операций одного профиля.

**Подтверждено:** после изменения секрета следующий mint по истечении токена
использует старое значение. Ошибка разрешения секрета превращается в запрос
с пустым `client_secret`.

**Критерий готовности:** ротация файлового секрета применяется на следующем mint;
нечитаемый секрет даёт локальную ошибку с именем профиля и reference, без mint
и без раскрытия значения.

Код: [auth/oauth2.go](../internal/auth/oauth2.go).

- [x] Расширить модель audit outcome: отказ до отправки, успешное исполнение,

- [x] Учитывать стадию вызова и факт попытки обращения к upstream.
- [x] Не обозначать любой transport error как `refused`.
- [x] Для мутаций после потери ответа сообщать агенту, что результат может быть

- [x] При изменении публичной формы событий документировать совместимость.

**Подтверждено:** после вызова transport, завершившегося ошибкой,

**Критерий готовности:** тест, в котором API выполнил мутацию, но ответ потерян,
не сообщает об отказе до отправки. Политический отказ остаётся отдельным исходом
и гарантирует отсутствие обращения к upstream.

Код: [mcpserver/runner.go](../internal/mcpserver/runner.go),

### 6. Исправить обработку JSON `null` в request body

- [x] Различать отсутствующий `body` и явно переданный `body: null`.
- [x] Сериализовать допустимый схемой `null` как JSON `null`.
- [x] Согласовать обязательность тела с опубликованной схемой.

**Подтверждено:** обязательный nullable body проходит валидацию, но отклоняется
при сборке запроса; необязательный `null` превращается в отсутствие тела.

**Критерий готовности:** покрыты отсутствующее тело, `null`, объект и скаляр
для обязательного и необязательного request body; запрос соответствует схеме.

Код: [requestbuild/requestbuild.go](../internal/requestbuild/requestbuild.go).

### 7. Гарантировать уникальность имён инструментов

- [x] Зарезервировать имена встроенных инструментов, включая `ping`.
- [x] Повторно проверять имя после добавления collision suffix.
- [x] Проверять уникальность окончательного каталога перед регистрацией в SDK.

**Подтверждено:** `operationId: ping` заменяет встроенный инструмент. Также

**Критерий готовности:** ни одна операция не исчезает при регистрации из-за
совпадения имени; проверены служебные имена, одинаковые operationId, усечение
длинных имён и совпадение с уже сгенерированным суффиксом.
